Interception points in agent safety benchmarks

First author · NeurIPS 2026 workshop submission

Agent safety benchmarks report how often an agent produces a harmful outcome, and a safeguard that drives that rate down is read as evidence it works. But a safeguard also removes the event the metric counts — so the number left behind can describe the harness rather than the agent.

I tested this by changing only where a safeguard intervenes, holding the agent, the attacks and the scenario fixed: 1,281 trials of an attacker agent working a medical records-desk assistant for synthetic patient data. Which metric collapses follows the interception point. A deterministic gate at the tool holds unauthorised access at exactly 0.00 — the same value in four conditions — and leaves disclosure unmeasurable. A model reviewer on the output leaves access untouched and holds disclosure at 0.02.

The near-zero is the more dangerous of the two: the gate's zero is definitional, flat at every turn cap, while 0.02 is stochastic and passes for an ordinary rate. Keeping the counterfactual observable rather than deleting it — a decoy record instead of a refusal, the vetoed draft instead of nothing — recovers a measured 0.91 interception rate. A floor that moves with the interception point is a fact about the harness, not the agent.

MedeFence — multi-agent red-team testbed

2026

Python · LLM agents · deterministic evaluation

A two-agent testbed for studying inter-agent manipulation. An autonomous attacker agent tries to talk a medical records-desk assistant into disclosing protected health information without completing identity verification — the interesting failure mode being identity confusion, not content leakage. There is no string the agent must never say; it must say the right thing to the right person.

Scoring runs on a deterministic finite-state machine over the tool ledger rather than an LLM judge, so the primary signal carries no false positives: 1,281 trials across five attack strategies, a 2×3 factorial of tool defenses, and a monitor arm. Everything is sandboxed — synthetic patients, mock tools, and models under my own control.

jobwatch — a job-search pipeline I actually use

2026

Python · SQLite / Turso · GitHub Actions · Streamlit

A daily poller across roughly 1,100 public ATS boards — Greenhouse, Lever, Ashby, SmartRecruiters, Workable, Recruitee — that classifies each posting by level, domain and sponsorship language, deduplicates on company, title and location, and files everything into a triage portal for tracking applications and referrals.

It runs unattended on GitHub Actions against a hosted libSQL database, with incremental anti-join inserts so a re-run never duplicates a row. The interesting part was making it survive without me: retries on expired connection streams, a keepalive that stops the scheduled workflow being auto-disabled for inactivity, and enough logging that a genuinely quiet day is distinguishable from a broken one.
